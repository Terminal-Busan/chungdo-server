# PRD — Welfare Next

> 복지정책에서 탈락한 사람을 방치하지 않고, 탈락 사유부터 다음 지원정책까지 이어주는 AI 복지 네비게이터

- 문서 버전: v1.0 (2026-11-05, 청도 바이브코딩 해커톤)
- 배포 URL: https://chungdo-client-dev-fabjesb7hpedbhd9.japaneast-01.azurewebsites.net (프론트 dev 배포, Azure App Service)
- API 문서: `<백엔드 주소>/docs` (백엔드 `chungdo-server-dev` App Service, 주소 [확인 필요])
- 로그인: **없음** (누구나 바로 핵심 기능 사용 가능)

---

## 1. 개요

Welfare Next는 복지정책 신청에서 탈락한 사용자가 **탈락 통지 내용과 자신의 조건을 입력하면**, GitHub Copilot SDK로 GPT 모델에 연결된 3개의 AI 에이전트(사유해석 → 정책매칭 → 경로설계)가 서버의 순차 오케스트레이션으로 협업해 다음을 한 번에 제공하는 웹 앱이다.

1. 왜 탈락했는지 쉬운 말 설명
2. 현재 조건으로 신청 가능한 대체 정책과 조건별 비교
3. 재신청·추가서류·이의신청 등 다음 행동 체크리스트와 신청 순서(복지 경로)

## 2. 문제 정의 (생산성 관점)

| 현재 사용자가 하는 일 | 문제 |
|---|---|
| 탈락 통지서의 행정용어("소득인정액 초과", "기준 중위소득" 등)를 직접 검색 | 이해하는 데 시간이 오래 걸리고, 이해하지 못한 채 포기하기도 함 |
| 다른 지원정책을 처음부터 다시 검색 | 정책마다 자격조건 표기가 달라 하나씩 비교해야 함 |
| 자신이 어느 조건에서 떨어졌는지 모른 채 비슷한 정책에 재신청 | 같은 이유로 반복 탈락, 서류 준비 시간 낭비 |
| 이의신청 가능 여부와 방법을 별도로 찾음 | 정보가 흩어져 있어 행동으로 이어지지 않음 |

핵심 문제: **탈락 이후 "다음에 무엇을 해야 하는지"까지 걸리는 개인의 탐색·판단 시간이 너무 길고, 그 과정에서 포기가 발생한다.**

> 탈락 후 재신청 포기율, 평균 탐색 시간 등 정량 통계: [출처 확인 필요] — 확인 전까지 PRD에 수치를 쓰지 않는다.

## 3. 대상 사용자

**주 페르소나: 사회 초년생 1인 가구 청년 (예: 27세, 대구·경북 거주, 월세, 비정규직)**
- 주거 관련 지원을 신청했다가 소득 기준으로 탈락
- 복지 제도를 처음 알아보는 사람이라 행정용어에 익숙하지 않음
- 모바일로 짧은 시간 안에 결론을 원함

**보조 페르소나: 가족 대신 복지를 알아보는 보호자** (부모님 정책 탈락 후 대안 탐색)

## 4. 목표와 성공 지표

| 목표 | 지표 (데모에서 측정) |
|---|---|
| 탈락 사유 이해 시간 단축 | 입력 완료부터 사유 설명 표시까지 30초 이내 |
| 대체 정책 탐색 시간 단축 | 입력 1회로 대체 정책 후보 + 조건 비교표 제공 (수동 검색 0회) |
| 행동 전환 | 결과 화면에 최소 1개 이상의 구체적 다음 행동(서류·신청처·순서) 제시 |
| 신뢰 | 추천된 모든 정책이 정부24 데이터에 실재하고, 자격 판정은 코드 규칙으로 계산됨 (환각 0건) |

## 5. 범위

### In Scope (해커톤 MVP)
- 로그인 없는 단일 흐름: 입력 → 에이전트 분석(실시간 진행 표시) → 결과
- 정책 데이터: 정부24 공공서비스(혜택) 정보 API(공공데이터포털)를 동기화해 사용 (중앙부처·지자체·공공기관 혜택)
- "시연 사례 입력" 버튼 (심사자·처음 사용자가 예시값을 자동 입력해 즉시 체험)
- 분석 결과 삭제 기능 (개인정보 통제권)

### Out of Scope
- 실제 정부 시스템 연동 및 대리 신청
- 회원가입, 결과 장기 보관
- 전체 복지정책 크롤링 (향후 계획)

## 6. 기능 요구사항

| ID | 기능 | 우선순위 | 담당 에이전트 | 구현 상태 (제출 시점) |
|---|---|---|---|---|
| F1 | 탈락 사유 쉬운 말 설명 | P0 | 사유해석 에이전트 | 백엔드·화면 완료 |
| F2 | 사용자 조건 기반 대체 정책 추천 | P0 | 정책매칭 에이전트 | 백엔드·화면 완료 |
| F3 | 정책별 자격조건 비교표 | P0 | 정책매칭 에이전트 + 규칙 판정 | 백엔드·화면 완료 |
| F4 | 다음 행동 안내 (재신청·추가서류·이의신청) | P0 | 경로설계 에이전트 | 백엔드·화면 완료 |
| F5 | 복지 경로 (신청 순서) 생성 | P1 | 경로설계 에이전트 | 백엔드 생성 완료, 화면 표시 예정 |
| F6 | 분석 결과 삭제 (확인 창) | P1 | — | 백엔드 API 완료, 화면 연결 예정 (미삭제 시 24시간 후 자동 만료) |

### F1. 탈락 사유 쉬운 말 설명
- 입력: 탈락한 정책(정부24 서비스 검색에서 선택), 탈락 통지 문구(선택, 붙여넣기), 사용자 조건
- 출력: 어떤 조건에서 떨어졌는지(조건명 / 내 값 / 기준 값), 중학생도 이해할 수 있는 설명 3문장 이내, 행정용어 풀이
- 수용 기준: 판정 근거가 된 기준 값은 정부24 데이터(지원조건 코드·선정기준 원문)만 사용. DB에 없는 기준은 "확인 필요"로 표시
- 수용 기준: 지원조건 코드상 미충족 조건이 없으면(재산·소득인정액 등 코드로 표현되지 않는 기준으로 탈락한 경우) `failed_criteria`를 비우고, 화면에는 "담당 기관의 선정기준 확인이 필요해요"로 안내한다. 단정적으로 "이 이유로 탈락했다"고 쓰지 않는다
- 수용 기준: 통지 문구나 정책 원문에 "소득인정액"이 있으면 월 소득만으로 확정할 수 없으므로 소득 조건을 "확인 필요"로 둔다

### F2·F3. 대체 정책 추천과 조건 비교
- 정책매칭 에이전트가 `search_policies` 도구로 후보를 찾고, `check_eligibility` 도구(코드 규칙)로 조건별 충족 여부를 계산
- 출력: 정책별 `충족 / 미충족 / 확인 필요` 조건 비교표, 추천 이유 한 줄
- 수용 기준: 추천 정책은 반드시 정부24에서 동기화된 서비스ID. 판정 결과는 LLM이 아니라 규칙 함수의 결과를 그대로 표시

### F4·F5. 다음 행동과 복지 경로
- 출력: 행동 유형(`재신청 reapply` / `추가서류 documents` / `이의신청 appeal` / `신규신청 apply_new`), 필요 서류, 신청처, 순서와 이유
- 수용 기준: 기한·금액 등 DB에 없는 사실은 생성하지 않고 "통지서 또는 신청처에서 확인"으로 안내

### F6. 결과 삭제
- 백엔드 `DELETE /api/navigations/{id}`로 입력과 결과, 에이전트 로그를 함께 삭제한다
- 화면: "분석 결과 삭제" → 확인 창 → 삭제 후 첫 화면으로 이동 (연결 예정). 연결 전에는 24시간 자동 만료로 보관 기간을 제한한다

## 7. 사용자 흐름

1. 메인 화면에서 "내 상황으로 찾아보기"로 같은 페이지의 입력 폼(`#analysis-form`)으로 이동하거나, "시연 사례 입력"으로 예시값 자동 입력
2. 신청했던 정책 이름 입력 → [정책 검색] → 정부24 검색 결과에서 선택
3. 탈락 사유(선택), 나이, 가구 형태·가구원 수, 월 소득(원), 거주 지역, 주거 형태, 경제활동 상태, 장애 여부 입력 → 24시간 임시 저장 동의
4. [다음 지원 찾기] → "조건을 확인하고 있어요" 표시 중 서버에서 3개 에이전트가 순서대로 실행 (SSE)
5. 결과 화면: [왜 탈락했나요?] → [지금 검토해볼 지원] (조건 비교, 정책 상세 창) → [다음에 무엇을 하면 되나요?]

## 8. 화면 목록

| 화면 | 목적 | 호출 API (프론트 `/backend` 프록시 경유) |
|---|---|---|
| 메인 `/` (소개 + 입력 폼 `#analysis-form`) | 서비스 소개, 정책 검색·선택, 탈락 사유·조건 입력, 동의, 시연 사례 입력 | `GET /api/policies`, `POST /api/navigations` |
| 결과 `/result` | 분석 진행 표시, 결과 3섹션 (탈락 이유 / 검토해볼 지원과 조건 비교 / 다음 행동), 정책 상세 창 | `GET /api/navigations/{id}/stream` |

## 9. 책임 있는 AI 요구사항

- 결과와 페이지 하단에 "참고용 안내이며 최종 자격 판단은 담당 기관에 있다"는 고지 표시
- 자격 판정은 규칙 코드로 계산하고, AI는 설명만 담당 (AI는 판정 값을 바꿀 수 없음, 서버가 출력 검증·교정)
- 이름·주민등록번호·연락처를 받지 않음. 통지 문구와 AI 출력의 주민번호·전화번호 패턴은 서버에서 마스킹
- 사용자 입력은 "데이터"로만 취급 (프롬프트 인젝션 대응), AI 세션에는 파일·셸·외부 쓰기 도구를 주지 않음
- 저장 전 동의 필수, 분석 결과는 24시간 후 자동 만료
- AI 호출 실패 시 규칙 기반 설명으로 대체하고 `ai_generated=false`로 구분

## 10. 데모 시나리오 (심사용)

1. 배포 URL 접속 (로그인 없음) → "시연 사례 입력" 클릭
2. 예시값 자동 입력: 주거지원, "소득인정액이 기준을 초과해 지원 대상에서 제외", 27세, 1인 가구, 월세, 재직, 월 250만원, 경상북도 청도군
3. [정책 검색] → 검색 결과에서 신청했던 정책 선택 → 저장 동의 체크
4. [다음 지원 찾기] → 서버에서 사유해석 → 정책매칭 → 경로설계 에이전트가 순서대로 실행
5. 결과에서 탈락 이유, 검토해볼 지원과 조건 비교(입력 조건과 일치 / 조건이 맞지 않음 / 추가 확인 필요), 다음 행동 확인
